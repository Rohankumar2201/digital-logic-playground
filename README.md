# Digital Logic Playground

An interactive, in-browser digital logic simulator. Drag gates, flip-flops and building blocks onto a canvas, wire them together, flip switches, run a clock, and watch signals propagate live. No backend, no account, everything runs in your browser.

**Live demo:** https://your-deployment-url-here

![Screenshot](docs/screenshot.png)

## Features

- **20 components**
  - Input: switch, clock
  - Logic: AND, OR, NOT, NAND, NOR, XOR, XNOR
  - Sequential: D, JK and T flip-flops
  - Building blocks: 2:1 MUX, 4:1 MUX, 1:2 DEMUX, 2-to-4 decoder, 4-to-2 encoder, half adder, full adder
  - Output: LED
- **Real simulation.** Combinational logic settles until stable; flip-flops sample together on a rising clock edge, so chained flip-flops behave like real hardware. Feedback oscillation is detected and reported.
- **Wiring with validation.** Output-to-output, input-to-input, self-driving and double-driven inputs are rejected with a clear message.
- **Truth tables.** A per-component table in the side panel, plus a whole-circuit table generated by trying every switch combination. Export as CSV or copy to the clipboard.
- **Undo / redo** (100 steps), multi-select, Delete, and Clear All with confirmation.
- **Save / load** to browser storage, and **export / import** as a versioned `.json` file with strict validation.
- **Examples:** AND, XOR, half adder, full adder, 4:1 MUX, D flip-flop.
- **Pan and zoom canvas**, grid snapping, dark and light theme.

## Getting started

Requires [Node.js](https://nodejs.org) 18 or newer.

```bash
git clone https://github.com/<your-username>/digital-logic-playground.git
cd digital-logic-playground
npm install
npm run dev
```

Open the URL Vite prints (usually http://localhost:5173).

### Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Start the dev server with hot reload |
| `npm run build` | Type-check with `tsc`, then build to `dist/` |
| `npm run preview` | Serve the production build locally |
| `npm test` | Run the test suite once with Vitest |

## How to use

| Action | How |
|---|---|
| Add a part | Drag it from the left list onto the canvas, or click it |
| Wire two pins | Drag from an output pin to an input pin (Esc cancels) |
| Unplug a wire | Drag it off the input pin it ends on |
| Toggle a switch | Click it |
| Pulse a clock | Click it; use Run in the side panel for a 1 Hz clock |
| Select several | Shift-click, or Ctrl/Cmd + A for everything |
| Delete | Delete or Backspace, or the Delete button |
| Undo / redo | Ctrl/Cmd + Z, Ctrl/Cmd + Y (or Shift + Z) |
| Pan | Drag the background, or hold Space and drag |
| Zoom | Mouse wheel |
| Rename a switch or LED | Select it and edit the name in the right panel |

## Project structure

```
src/
├── types.ts              shared data types (Comp, Wire, Circuit, ...)
├── simulator/            pure TypeScript logic, no React
│   ├── components.ts     definition table for every component type
│   ├── engine.ts         settle(), input lookup, add component, wiring rules
│   ├── circuit.ts        delete/connect, validation, file format, truth table
│   ├── interaction.ts    pointer gesture logic (press, move, release, wire)
│   └── edit.ts           commit and undo/redo on top of history
├── components/           React UI (Canvas, Toolbar, Sidebar, InfoPanel, TruthTable)
├── circuits/examples.ts  example circuits as compact specs
├── utils/                geometry, history, selection, keyboard, file download
├── tests/                Vitest suites
└── App.tsx               owns all state and connects the pieces
```

The key design rule is that the simulator contains no React. The UI draws the circuit and forwards input; all behaviour lives in functions that can be tested on their own. Every edit returns a new `Circuit` object rather than mutating the old one, which is what makes undo simple.

## Circuit file format

Exported files look like this:

```json
{
  "version": 1,
  "circuit": { "comps": [], "wires": [], "nid": 1 },
  "view": { "x": 40, "y": 20, "k": 1 }
}
```

Imports are validated before anything changes: unknown component types, invalid pins, duplicate ids, double-driven inputs and out-of-range values are rejected rather than silently repaired.

## Limits

- 2000 components and 5000 wires per circuit
- Import files up to 2,000,000 characters
- Whole-circuit truth tables support up to 10 switches and circuits without clocks or flip-flops, since a static table cannot describe time-dependent behaviour

## Testing

```bash
npm test
```

The suites cover each component's truth table, wired simulation, flip-flop edge behaviour, connection rules, undo semantics, pointer gestures, truth-table reliability, and import validation against malformed files.

## Deployment

It is a static site. `npm run build` produces `dist/`, which can be hosted on Vercel, Netlify, GitHub Pages or any static host. When deploying under a sub-path (for example GitHub Pages), set `base` in `vite.config.ts` to the repository name.

Browser-saved circuits live in `localStorage`, so they are per browser and per domain. Use Export and Import to move circuits between machines.
